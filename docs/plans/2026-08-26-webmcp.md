# WebMCP Sound Design Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Turn coSynth into an agent-native browser synthesizer by exposing a small, composable WebMCP tool API over the same live synth state used by the human UI.

**Architecture:** Add a typed WebMCP adapter that receives the existing `SynthEngine`, derives semantic schemas from the canonical parameter/modulation registries, validates all inputs in handlers, and registers tools only when `document.modelContext` is available. Add a real-time recorder tap to the existing AudioWorklet output and pure audio-analysis functions so `render_audio` can return both playable audio and deterministic numeric feedback. Keep WebMCP as progressive enhancement: the synth must work unchanged in browsers without the API.

**Tech Stack:** TypeScript 5.5, Vite 8, Web Audio/AudioWorklet, WebMCP `document.modelContext.registerTool`, `webmcp-types`, Vitest, Playwright smoke automation.

### Task 4: Add recording and audio feedback

**Objective:** Let an agent audition a patch and receive actual audio plus useful DSP metrics in one loop.

**Files:**
- Modify: `src/audio/engine.ts`
- Create: `src/shared/audio-analysis.ts`
- Create: `src/shared/audio-analysis.test.ts`
- Modify: `src/webmcp/tools.ts`
- Modify: `src/webmcp/tools.test.ts`

**Tools:**
- `render_audio`
- `analyze_audio`

**Steps:**
1. Write failing pure tests for peak/RMS dB, clipping count, DC offset, spectral centroid, attack time, and stereo width using generated signals.
2. Add a bounded real-time `SynthEngine.recordOutput(duration, signal?)` path by connecting the existing worklet node to a `MediaStreamAudioDestinationNode`, recording with `MediaRecorder`, decoding through the existing `AudioContext`, and disconnecting/cleaning up in `finally`.
3. Implement `render_audio` to schedule validated notes while recording, return a stable blob URL, MIME type, duration/sample rate/channel count, and metrics. Clearly report `renderMode: "realtime"` rather than claiming offline determinism.
4. Implement `analyze_audio` over the most recent render, with a fallback to the current scope buffer and explicit source metadata.
5. Bound renders to 15 seconds, honor cancellation, revoke the previous render URL, and always release notes.

## Acceptance criteria

- Exactly these nine composable tools are registered: `get_synth_state`, `get_parameter_schema`, `update_parameters`, `set_modulation`, `play_notes`, `render_audio`, `analyze_audio`, `save_preset`, `load_preset`.
- Every tool has a non-empty description, object input schema, strict runtime validation, JSON-serializable output, correct read-only annotation, and a handler that honors cancellation where work is asynchronous.
- Parameter changes and modulation updates go through `SynthEngine` APIs so the human UI observes them.
- `render_audio` produces non-silent recorded audio and useful numeric metrics after audio has been user-started; it identifies itself honestly as real-time rendering.
- The application works without WebMCP, on localhost and in the production build.
- Unit tests, typecheck, build, existing audio smoke, and WebMCP smoke all pass.
